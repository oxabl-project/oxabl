# Brainstorm: Lexer Runtime Allocation Removal

**Date:** 2026-04-04
**Status:** Ready for planning

## What We're Building

Three surgical performance fixes that eliminate unnecessary heap allocations and runtime string comparisons in the lexer and parser hot paths.

### Problem

The lexer's `match_keyword()` function calls `s.to_lowercase()` on **every token** — producing a heap-allocated `String` per identifier. ABL is keyword-heavy, so this hits on nearly every token in a source file. The lock-type detection path has the same issue. The parser also has one `eq_ignore_ascii_case` workaround for file extension checking that should be handled more efficiently.

### Scope

1. **`match_keyword()` in `kind.rs:541`** — Replace `s.to_lowercase()` with a `[u8; 64]` stack buffer that folds ASCII case in-place. Zero heap allocations.
2. **`try_read_space_separated_lock()` in `lib.rs:334`** — Replace `first_word.to_lowercase()` with byte-level ASCII case folding or `eq_ignore_ascii_case`.
3. **Parser file extension check in `statements.rs:1556-1560`** — Replace `eq_ignore_ascii_case("p")` etc. with direct byte-value matching on the single-char/short extensions.

### Out of Scope (tracked for follow-up)

- Activating the dormant `atom!()` macro infrastructure for pointer-equality comparisons
- Broader parser string comparison audit

## Why This Approach

- **Highest impact, lowest risk.** The `match_keyword()` allocation runs on every token — it's the single hottest string allocation in the lexer. Removing it is a clear win.
- **ABL keywords are ASCII-only.** Case folding is conditional `| 0x20` on `A-Z` bytes only; hyphens, spaces, and digits pass through unchanged. No Unicode complexity.
- **Stack buffer is sufficient.** The longest ABL keyword is ~25 chars. A 64-byte stack buffer covers everything with margin. No external dependencies needed.
- **Codegen owns `match_keyword()`.** The fix goes into `oxabl_codegen`'s template, so it's generated consistently and never hand-maintained.

## Key Decisions

1. **Stack buffer strategy:** Plain `[u8; 64]` array on the stack. Copy source bytes while folding `A-Z` to `a-z`. Slice the buffer for the match expression. If the input exceeds 64 bytes, it can't be a keyword — return `None` immediately.
2. **Lock-type detection:** Replace the `to_lowercase()` + `match` on line 334 with three `eq_ignore_ascii_case` calls against `"no"`, `"share"`, `"exclusive"` directly on the `&str` slice. The existing `eq_ignore_ascii_case("lock")` check on line 368 is already correct.
3. **File extension check:** Match on byte length + lowercase bytes. Single-char extensions (`p`, `w`, `r`, `i`) are one byte comparison. `cls` is three bytes. No need for new `Kind` variants for something this narrow.
4. **Codegen integration:** The `match_keyword()` change is generated by `oxabl_codegen`, so the fix is a template change in the codegen crate, not a manual edit to `kind.rs`.
